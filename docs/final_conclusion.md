## 0. 한 줄 결론

> **핵심질문 "왜 뉴스 검색은 원하는 기사를 못 찾아오나?"에 대한 답:
> 파이프라인을 4단계로 쪼개 측정한 결과, 리랭킹과 생성은 이미 충분하고
> 1차 검색의 상한(Recall ceiling 0.536)이 전체 성능의 병목임을 수치로 확인했다.**

---

## 1. 핵심 질문 (중간발표 슬라이드 2)

> "왜 뉴스 검색 시스템은 원하는 기사를 못 찾아오는가?"

이 프로젝트는 막연히 "검색이 안 된다"가 아니라, **검색 실패를 단계별로 분해해 측정**하는 것이 목표였다.

### 가설 — 3가지 구조적 실패 (슬라이드 3)
| # | 실패 유형 | 예시 |
|---|---|---|
| ① | 의미 혼동 | "AI 반도체" 질문 → "AI 컴퓨터" 기사 |
| ② | 오래된 기사 | "최근 LLM 동향" 질문 → 1년 전 GPT-3 기사 |
| ③ | 키워드 불일치 | "삼성 AI 발표" → "삼성"만 일치, AI 무관 |

### 해결 설계 — 4단계 파이프라인 + 단계별 측정 (슬라이드 4)
```
Hybrid Retrieval → Reranker → Temporal Weight → LLM 답변 생성
(키워드+의미)      (재정렬)    (최신 가중치)     (근거 인용 답변)
        ↑ 각 단계마다 성능을 측정해 향상을 수치로 증명
```

## 2. 결과 1 — Retrieval Ablation (팀 A)

### 5개 검색 방식 비교 (Positive QA 21개, Recall@5)
| 모델 | Recall@5 | 순위 |
|---|:---:|:---:|
| **Hybrid (BM25+BGE-M3 RRF)** | **0.417** | 🥇 |
| BGE-M3 | 0.401 | 🥈 |
| ko-sroberta | 0.353 | 🥉 |
| BM25 | 0.306 | 4 |
| OpenAI text-embedding-3-small | 0.206 | 5 |

→ **발견 A-1**: 범용 OpenAI 임베딩이 꼴찌. 한국어 AI 뉴스 도메인에선 도메인 특화 모델이 우세.

### Query 특성별 최적 모델 (핵심 기여)
| Query 특성 | 최강 모델 | Recall@5 |
|---|---|:---:|
| Lexical (특정 엔티티) | Hybrid | 0.575 |
| Semantic (트렌드/동향) | BGE-M3 | 0.364 |
| 🇰🇷 한국어 고유명사 (삼성전자, SKT) | ko-sroberta | 0.688 |
| 🔤 영문 기술용어 (OpenAI, NVIDIA, HBM) | BGE-M3 | 0.528 |

→ **발견 A-2**: 단일 최강 모델은 없다. 질문 특성마다 강한 모델이 다르다 → Hybrid가 평균적으로 가장 안정적.

## 3. 결과 2 — Reranker Fine-tuning (팀 B) ⭐ 모델 개선 핵심

### 무엇을 했나
- 팀 A의 Hybrid top-10 결과에서 **Hard Negative**(정답 아닌 헷갈리는 오답) 추출
- (query, positive, negative) Triplet **486쌍** 구축
- `klue/bert-base` Cross-Encoder를 **직접 미세조정(fine-tuning)**

### 효과 (before / after)
| 지표 | 1차 검색(Baseline) | + Reranker | 향상 |
|---|:---:|:---:|:---:|
| Recall@5 | 0.425 | **0.536** | +0.111 |
| **MRR** | **0.43** | **0.81** | **약 2배** |
| nDCG@5 | 0.344 | 0.601 | +0.257 |

### QA 타입별
| 타입 | Baseline | Reranker | 향상 |
|---|:---:|:---:|:---:|
| Strict (단일 정답) | 0.476 | 0.690 | **+21.4%p** |
| Trend (다수 정답) | 0.399 | 0.458 | +6.0%p |

→ **발견 B-1**: Reranker는 단일 정답형 질문에서 압도적. MRR 2배 = 정답이 평균 1.2등 안에 옴.
→ **발견 B-2 (중요)**: Reranker 적용 후 Recall@5(0.536) = **Improvement Ceiling(0.536)에 100% 도달**.
   즉 "1차 검색이 top-10에 정답을 넣어주기만 하면 Reranker가 100% 위로 끌어올린다."
   **Reranker는 완벽 → 남은 한계는 1차 검색이 top-10 안에 정답을 절반(0.536)밖에 못 넣는 것.**

> 📌 교수님 포인트("어떻게 모델을 향상시켰나")의 메인 답 = 이 Cross-Encoder fine-tuning.
> 단순 비교가 아니라 도메인 데이터로 직접 학습시켜 MRR을 2배로 끌어올림.

## 4. 결과 3 — Temporal RAG + RAGAS 평가 (팀 C)

### RAGAS 3대 지표 (Positive QA 21개 평균)
| 지표 | 점수 | 해석 |
|---|:---:|---|
| Answer Similarity | **0.861** | 답변이 정답과 의미적으로 매우 유사 🟢 |
| Context Precision | **0.679** | 검색 문서 정밀도 보통 🟡 |
| Faithfulness | **0.608** | 근거 충실도 (아래 Failure Analysis 주의) 🟡 |

## 5. Failure Analysis — 발표 핵심 ⭐

### Faithfulness 0점 7개를 직접 분해
**중요**: Faithfulness 평균 0.608은 "환각 40%"가 **아니다**.
0점 7개를 까보니 전부 동일한 답: **"제공된 뉴스에서 관련 내용을 찾을 수 없습니다"**
= 거짓말(환각)이 아니라 **과도한 답변 회피(over-abstention)**.

### 7개를 책임 단계별로 분류
| 유형 | 개수 | 정밀도 | 진단 | 책임 단계 |
|---|:---:|:---:|---|---|
| 검색 실패 → 올바른 회피 | 5 | 낮음(0~0.58) | 검색이 엉뚱한 뉴스 → AI가 정직하게 거부 (안전) | **검색** |
| 검색 성공 → 과도한 회피 | 2 | 1.00 | 딱 맞는 뉴스 줬는데 AI가 소심하게 거부 (아까움) | **생성** |

예시:
- "한국 정부 AI 정책은?" → 검색이 '앤트로픽 클로드 사용자수' 뉴스를 가져옴 → AI 올바르게 거부 (검색 책임)
- "AI 일자리·고용 영향은?" → 검색이 정답 뉴스를 가져왔는데(정밀도 1.0) → AI가 그래도 거부 (생성 책임)

→ **발견 C-1**: 우리 시스템은 환각을 거의 안 함. 안전성은 확보됨.
→ **발견 C-2**: 실패 7건 중 5건이 검색 책임 → **다시 검색 병목을 가리킴**.

## 6. 종합 결론 — 핵심 질문에 답하기

### 전체 ablation 체인 (슬라이드 8 "BM25 단독 대비" 약속 충족)
| 단계 | Recall@5 | 누가 |
|---|:---:|---|
| BM25 단독 | 0.306 | A |
| + Embedding/Hybrid | 0.417 | A |
| + Reranker | **0.536** | B |
| + Temporal/생성 | RAGAS로 별도 평가 | C |

### 결론
1. **리랭킹**(MRR 2배)과 **생성**(환각 없음)은 이미 충분히 좋다 → 검증 완료
2. **검색의 상한(0.536)이 전체 성능의 병목**이다
3. Failure Analysis도 실패 7건 중 5건이 검색 책임 → 같은 결론을 두 번 가리킴
4. **즉, "왜 뉴스 검색이 원하는 기사를 못 가져오나"의 답 = 1차 검색이 정답을 top-k에 못 올리는 것이 근본 원인. 리랭킹/생성으로는 그 천장을 못 넘는다.**
